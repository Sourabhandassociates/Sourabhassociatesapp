SAA FRONTEND - BUNDLE NUMBER UPDATE

Changes included:
- New Case form: Bundle Number input; sends bundleNumber with case creation.
- Case Details > Case Identification: displays Bundle Number.
- Edit Case Details: allows Bundle Number to be updated.
- Case Details > Hearing Details: displays Bundle Number.
- Hearings table and Hearing Timeline: include Bundle Number.
- Hearing Calendar: includes Bundle Number in the hearing list; hydrates it from case details if the hearing response omits it.
- Cases list: includes a Bundle Number column.

HOSTINGER BUILD / DEPLOY
1. Back up the current frontend deployment.
2. Extract this ZIP into the frontend project directory. Do not overwrite your environment configuration if you have one.
3. Run:
   npm ci
   npm run build
4. Upload the newly generated dist/ contents to your existing frontend web root.

IMPORTANT
- node_modules is intentionally excluded. npm ci installs platform-appropriate dependencies on Hostinger.
- The dist folder in this ZIP is the previous build output. It must be regenerated with npm run build before publishing; do not deploy the old dist as-is.
- TypeScript check passed in the preparation environment. A fresh Vite production build could not be completed here because the uploaded node_modules lacked the Linux Rollup binary.
- The backend API must already return and accept the `bundleNumber` property, and the database column must exist.
